# MVP 性能预算（测试前固定）

制定日期：2026-09-23。预算先于原型与完整实现的测量结果固定；超标应记录为未达标，不修改目标来掩盖问题。

## 环境与统计

开发设备上的 macOS 26.6.2；已安装 Chrome 154.0.8037.57。自动化使用独立的 Playwright Chromium（运行时记录准确版本、CPU、内存、视口），不得把其结果当作 Chrome 正式版人工验收。视口 1280×900，缩放 100%，固定本地测试集，不使用用户浏览器资料。

三组：未加载扩展、加载扩展但全局关闭、开启自动转换。每组独立浏览器上下文，正常页面 5 次冷导航；性能脚本顺序运行，记录每次原始数据及中位数、最近秩 p95。导航统一等待 load；区分导航后变暗时间、页面内容就绪后附加耗时，不能把不同定义混用。

| 项目 | 预先确定的预算 | 测量方法 |
|---|---|---|
| 首次生效 | 本地标准页导航起算 p95 首次变暗 ≤300ms、基本稳定 ≤800ms | 每帧计算 body 背景，连续 5 帧稳定；截图另作视觉检查，CSS 代理指标不等于屏幕闪白录像 |
| 主题切换 | 标准页 p95 ≤200ms；5000 节点页 ≤500ms | storage 写入前时间至两个渲染帧后可见背景符合目标 |
| 空闲 CPU | 稳定后 5 秒窗口较禁用增加 ≤1 个单核百分点 | CDP Performance.TaskDuration 增量 / 墙钟；标签页主线程口径，不代表全进程 CPU |
| 动态更新 CPU | 每 100ms 更新 100 节点，5 秒较禁用额外 ≤10 个单核百分点 | 相同操作的 TaskDuration；记录掉帧/长任务，不只报告平均值 |
| 内存 | 标准页增量 ≤20MiB，5000 节点页 ≤50MiB；后台 worker JS 堆 ≤10MiB | 强制 GC 后标签页 JSHeapUsedSize；另记录整个独立浏览器进程树 RSS，避免只看扩展后台 |
| 持续滚动/SPA | p95 帧间隔 ≤32ms，>50ms 长任务增加 ≤5 次/5秒 | requestAnimationFrame 间隔与 PerformanceObserver；固定脚本操作 |
| 反复切换 | 100 次后 GC 堆较第10次增加 ≤5MiB；关闭后无残留引擎样式 | 同一页面分段采样，观察停止后的稳定值；百次测试不能替代数小时验证 |
| 多标签页 | 5 个标签页稳定时累计主线程额外 CPU ≤3 个百分点；累计 JS 堆增量 ≤100MiB | 1 前台 + 4 后台，同步空闲窗口，累加各页指标并记录进程 RSS |

第一轮原型验证：背景/文字分层、动态内容、关闭恢复、可控页转换耗时及 JS 堆。完整实现之后按上述脚本复测。网络真实页面仅作为单独兼容性样本，不能与本地性能基线混算。

需人工补充：Chrome 稳定版实际工具栏 Popup、首屏录像、操作系统进程 CPU、数小时运行、视频播放及滚动主观体验。未执行不得记为通过。

## 测量实现说明（不调整上表预算）

最终 CPU 测量每种状态、每种页面各做 3 个 5 秒窗口，报告中位数并保留原始窗口。首次生效采用同一全新 profile 内 5 次新文档导航；它不是每次都重启浏览器和清空所有缓存的严格冷启动，所以上述“冷导航”不能解读为全冷启动已验证。严格冷启动与实际屏幕闪白仍需补测。

Playwright 默认会禁用后台节流；性能脚本移除了这三项禁用参数，保留 Chrome 的后台调度。每次完整运行重新测量全部三组，避免将不同构建或环境的结果拼接。原始结果写入本地 test-results/performance.json。
