# 通用背景层次修复

日期：2026-09-28。

## 原因与修复范围

原背景映射把 RGB 通道差小于 50，或 HSL 亮度大于 0.93 的颜色归入中性色。浅蓝、浅红、浅绿等提示背景容易因此失去色相。浅灰背景又按 `(1 - lightness) * 0.16` 提亮，接近白色的标签转换后与页面背景只差几个 RGB 色阶。

生产改动集中于 `src/colors.js` 的通用调色板，没有增加域名判断、网站选择器、DOM 扫描、网络请求或专用 CSS。示例站点的 URL 和选择器仅存在于真实网站测试脚本。

- 白色仍映射到用户选择的基准背景；用有上限的连续曲线拉开浅灰层次，纯黑主题适当增加幅度，中间灰与深灰分支连续衔接。
- 通过饱和度和通道差平滑引入原色相，避免浅色背景在阈值两边突然变灰，或近白底色被过度染色。
- 浅彩色背景按相对亮度约束，防止同一 HSL 亮度的黄色远亮于蓝色。限制随原始亮度平滑生效。
- 文字的对比保护以提亮后的中性背景上限为参考，覆盖常见提示、胶囊中的彩色链接。用户主动选择低对比度配色时沿用原有尊重设置的行为。
- 保留透明度、透明占位、CSS 变量作用域、伪元素、行内优先级与渐变结构，继续使用原有有界颜色缓存。

## 颜色示例

默认背景为 RGB 24、28、36。下表是相同原始颜色的算法输出，背景间比值用于比较层次，不作为文字可读性标准。

| 原始背景 | 修改前 | 修改后 | 与页面背景亮度对比（前 → 后） |
| --- | --- | --- | --- |
| 白色 #ffffff | 24, 28, 36 | 24, 28, 36 | 1.00 → 1.00 |
| 浅蓝 #d1f0ff | 27, 31, 40 | 14, 55, 76 | 1.03 → 1.36 |
| 浅灰 #f2f2f2 | 26, 30, 38 | 39, 45, 58 | 1.02 → 1.24 |
| 灰色 #e8e8e8 | 27, 31, 40 | 44, 52, 66 | 1.03 → 1.36 |

- `npm test`：18 项通过。新增浅灰层次、六个色系的色相、渐变连续性、透明度、深色遮罩，以及四套基准色下浅彩色背景与常见文字/链接组合的 4.5:1 对比检查。
- `npm run test:surfaces`：4 组浏览器回归通过，包含背景变量、RGB 通道变量、行内与 important 声明、伪元素、悬停、嵌套、半透明、动态改色及关闭恢复。
- `npm run test:dark`：7 组既有回归通过。
- `npm run test:e2e`：15 组既有回归通过，包括原生主题切换、浮层、iframe、Shadow DOM、CSSOM 和重复开关。
- 真实站点抽查：Wikipedia、GitHub、Hacker News、MDN；记录自动转换、强制转换、滚动及关闭恢复。Wikipedia 另验证原生深色跳过及切回浅色后恢复转换。
- Linux.do：在应用浏览器中读取到提示底色 `rgb(209, 240, 255)`、胶囊底色 `rgb(242, 242, 242)`，确认与算法问题吻合；加载扩展的隔离 Chromium 收到 HTTP 403 验证页，未计为扩展实站通过。通用场景页覆盖了相同颜色和声明方式。

截图：`test-results/surfaces-light.png`、`test-results/surfaces-dark.png`。机器结果：`test-results/surfaces.json`、`dark-regressions.json`、`e2e.json`、`real-sites.json`。真实站点 JSON 保留了此前其他站点的记录，不能把那些旧记录当作本次复测。

## 边界

这是针对颜色映射的通用修复，不构成“绝大部分网站已全部验证”的结论。声明级调色板不能知道任意元素的最终叠加背景；图片背景、整元素 opacity、混合模式和高饱和深色实底上的全部文字组合不在本次对比度保证内。既有引擎的 CSS 支持边界仍适用。没有新增全页计算样式采样；本次未重跑完整性能对照，不据此宣称性能提升。
